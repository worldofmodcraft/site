# Design notes

Acceptance criterion 8 requires a distinctive, original, dark, "subtly fantasy-flavoured" design
with nothing Blizzard-derived anywhere (ADR-0004), and a log of how every decorative asset was
produced. This document is that log. Screenshots demonstrating the result at both a narrow phone
viewport and a wide desktop one are committed under `docs/screenshots/` (see the task log for the
exact command that produced each one).

No frontend-design skill was available in this environment (checked at the start of this task --
no matching skill in the available-skills listing), so the direction below was designed directly.

## Direction: "campfire at dusk"

Dark, warm-charcoal ground rather than pure black or a saturated "game UI" palette; one amber/ember
accent (interactive elements, headings' warm highlights) and one quiet moss-green counter-accent
(the eyebrow labels, tag chips) borrowed straight from the fixture content itself (campfires,
lanterns) rather than invented independently -- the palette and the placeholder mod content read as
one world, not two unrelated design exercises bolted together. Deliberately restrained saturation
throughout so it reads as a documentation/portal site with atmosphere, not a game HUD skin.

Full token list: `src/styles/global.css`'s `:root` block (`--color-*`).

## Typography

- **Display/headings:** [Cinzel](https://github.com/NDISCOVER/Cinzel) -- a Roman-inscription-
  inspired serif, wide letter-spacing at small sizes. Reads as "carved lettering" without being a
  literal fantasy game font, and pairs with the "campfire" direction without borrowing any game's
  specific identity.
- **Body:** [EB Garamond](https://github.com/octaviopardo/EBGaramond12) -- a classical old-style
  serif, chosen for long-form README and licensing prose to read comfortably at book-like line
  lengths (`max-width: 62-72ch` throughout).

Both are **SIL Open Font License 1.1**, self-hosted via the `@fontsource/cinzel` and
`@fontsource/eb-garamond` npm packages (installed like any other dependency -- `npm install`, no
separate download step, no CDN, no Google Fonts network request at build or runtime). Licence text
ships in `node_modules/@fontsource/{cinzel,eb-garamond}/LICENSE`. Only the Latin subset and the
weights actually used are imported (`src/layouts/BaseLayout.astro`) to keep the font payload small
-- see `docs/build.md`'s performance section for the measured total.

No system font stack fallback beyond generic serif families is needed since both fonts are
bundled, not loaded conditionally.

## Decorative art -- how each asset was produced

**Nothing here is a downloaded, copied, traced or AI-generated image.** Every visual asset is
either inline hand-authored SVG (checked into `.astro` component source, readable as markup) or a
PNG generated by a small from-scratch encoder written for this task (`src/lib/png.mjs`, plain
zlib deflate + PNG chunk framing, no image library dependency).

| Asset | File | How it was made |
|---|---|---|
| Favicon / site emblem | `public/favicon.svg` | Hand-authored inline SVG: two curved paths (a flame cradled by branch-like curves) drawn as raw path data, no source image, no vectorisation of anything. |
| Header wordmark icon | `src/components/SiteHeader.astro` | Same emblem, re-drawn as an inline `<svg>` in the component (kept in sync by eye since it is small and rarely changes -- not extracted to a shared file, a deliberately boring choice per ADR-0103 for something this size). |
| Section divider | `src/components/OrnamentDivider.astro` | Hand-authored inline SVG: two horizontal lines flanking a diamond, drawn as raw `<line>`/`<path>` elements. Colour comes from `currentColor` (inherits the page's border colour token), no raster asset at all. |
| Background wash on every page | `src/styles/global.css`, `body` rule | Two CSS `radial-gradient()`s (ember top-left, moss top-right) -- computed by the browser, zero bytes of image asset. |
| Fixture mod screenshots (6 PNGs) | `fixtures/archives-src/**/assets/screenshots/*.png`, generated by `scripts/make-fixture-screenshots.mjs` via `src/lib/png.mjs` | Each is a small procedural composition -- a gradient plus one simple geometric shape -- computed per-pixel by a JS function and encoded to a real PNG file (verified with `file` to be genuine 640x360 8-bit RGB PNGs, not placeholders with a `.png` extension). None reference, sample from, or approximate any Blizzard asset, palette, icon or logo. What each one represents: |
| &nbsp;&nbsp;`campfire.png` | | Warm vertical gradient (ember to charcoal) with a simple triangular "flame" silhouette. |
| &nbsp;&nbsp;`tales.png` | | Cool indigo gradient with a pale open-book silhouette (two trapezoids meeting at a spine). |
| &nbsp;&nbsp;`lantern-glow.png` | | Soft radial amber glow, no shapes -- a lit lantern post at dusk. |
| &nbsp;&nbsp;`mine-tunnel.png` | | Dark stone gradient with a pale rounded-arch tunnel mouth. |
| &nbsp;&nbsp;`lantern.png` | | Small warm radial glow off-centre on a near-black ground -- a hand lantern rather than a post. |

Fixture screenshots exist only to exercise the gallery UI against real (if invented) image files
pulled from a real (if invented) archive -- see `docs/build.md`'s "Fixture data" section for why
they must be deleted once real mods exist. They were never intended as finished "cover art"; their
job is to prove the pipeline reads real files from real archive paths, which `file` and a byte-
identical PNG signature check both confirm (see the task log).

## Responsiveness

No separate "mobile design" was drawn -- one fluid layout (CSS grid with `auto-fit`/`minmax`,
`clamp()` for heading sizes, a single-column stack below content's natural wrap points) is used
throughout, verified at both a narrow phone viewport (390 wide) and a wide desktop viewport
(1440 wide) via the committed screenshots. The one deliberately hand-tuned exception is the
version-history table on a mod page: it scrolls horizontally in its own `overflow-x: auto`
container on narrow screens rather than squeezing five columns unreadably, which is the same
pattern the artifact-authoring guidance in this environment recommends for wide tabular content.
